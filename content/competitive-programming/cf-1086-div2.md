# CF 1086 Div. 2

## Problem A

### Summary

Given an $n \times n$ matrix $A$ whose entries are integers in $[1, n^2]$, determine whether it is possible to arrange the numbers so that **no row or column is monochromatic** (i.e., contains only a single repeated value).

> [!claim]
> Such an arrangement exists **if and only if** no value appears more than $n^2 - n$ times.

### Proof

We start with an arbitrary arrangement and show that if the condition holds, we can gradually eliminate all monochromatic rows and columns.

Suppose row $i$ is monochromatic. Pick any cell $A(i,j)$. We attempt to swap it with another cell $A(k,j)$ such that:

- $k \ne i$,
- $A(k,j) \ne A(i,j)$, and
- row $k$ does not become monochromatic after the swap.

If such a swap exists, the number of monochromatic rows decreases by one.

Suppose **no such swap exists**. Then for every $k \ne i$, row $k$ must already contain $n-1$ copies of $A(i,j)$; otherwise the swap would not create a monochromatic row. The total number of cells equal to $A(i,j)$ would then exceed

$$
n + (n-1)(n-1) = n^2 - n + 1,
$$

contradicting the assumption that no value appears more than $n^2 - n$ times.

Hence such a swap must exist. By repeatedly applying this operation we eliminate all monochromatic rows. These swaps do **not** create new monochromatic columns, because the multiset of values in each column is unchanged. We then apply the same process to columns.

## Problem B

### Summary

Given a queue of length $n$, at each step you may select any element among the **first $k$** and move it to the end of the queue. Moving element $i$ costs $a_i$.

There is a **target element $p$**. The goal is to bring $p$ to the end of the queue as many times as possible within a total cost budget $m$.

### Greedy Strategy

1. If $p$ is among the first $k$, move it to the end and increment the count.
2. Otherwise, move the **cheapest element among the first $k$**.

### Proof of Optimality

Rather than analyzing a single move in isolation, we look ahead at the next $t > 1$ moves.

Suppose $p$ is currently at position $i > k$. Any strategy must eventually advance $p$ to position $k$ by removing the $i - k$ elements ahead of it. Let $A$ be the set of $i - k$ elements with **smallest cost** among the first $i - 1$ elements (those ahead of $p$).

**At least one element of $A$ lies among the first $k$.** If not, all $|A| = i - k$ elements of $A$ are among positions $k+1$ through $i-1$, but that range has only $i - k - 1$ positions — a contradiction.

Furthermore, the **cheapest element among the first $k$** must belong to $A$. Therefore, applying rule (2) exactly $i - k$ times moves all of $A$ to the end and brings $p$ to position $k$ at minimum cost

$$
\sum_{x \in A} a_x.
$$

Once $p$ reaches position $k$, we immediately move it to the end. Delaying would not improve the future strategy but would incur unnecessary cost.

After $p$ moves to the end, the minimum cost to bring it back to position $k$ is the sum of the $n - k$ smallest costs among the $n - 1$ elements preceding it.

## Problem C

### Summary

There are $n$ tasks processed in order. Each task $i$ gives reward $c_i$ and reduces stamina by $p_i\%$. Stamina starts at $S = 1$. Completing task $i$ earns $S \cdot c_i$ points and reduces stamina to $S(1 - p_i)$. Tasks may be skipped. Maximize total points.

### Key Insight

At first glance this resembles a knapsack problem, but the "budget" (stamina) is a **continuous multiplier**, making standard DP indexing infeasible.

The key observation is that processing tasks **in reverse** eliminates this difficulty.

Let $C$ denote the maximum future score achievable from the current state onward. When considering task $i$:

- **Skip:** $C$ is unchanged.
- **Perform:** all future rewards are scaled by $(1 - p_i)$, so the new future score is $C(1 - p_i) + c_i$.

The optimal choice is therefore

$$
\max\!\bigl(C,\; C(1-p_i) + c_i\bigr).
$$

Processing tasks from last to first yields a simple $O(n)$ DP.

## Problem D2

### Summary

A tree is converted into a directed graph by orienting each edge. Given a reachability matrix indicating whether vertex $v$ is reachable from vertex $u$, reconstruct the original tree or determine that the matrix is invalid.

### Characterizing Edges

> [!claim]
> There is a directed edge $u \to v$ if and only if:
>
> 1. $u \rightsquigarrow v$ (i.e., $v$ is reachable from $u$), and
> 2. there is no vertex $w$ such that $u \rightsquigarrow w$ and $w \rightsquigarrow v$.
>
> Condition (2) means $v$ is the **closest reachable descendant** of $u$.

**Proof.**

If $u \to v$ is an edge, condition (1) clearly holds. If condition (2) failed, there would exist $w$ with $u \rightsquigarrow w \rightsquigarrow v$. Together with the edge $u \to v$, this creates two distinct paths between $u$ and $v$ in the underlying undirected graph — a cycle, which is impossible in a tree.

Conversely, if $u \rightsquigarrow v$ but there is no direct edge, the path from $u$ to $v$ has length at least $2$, so there exists $w$ with $u \rightsquigarrow w \rightsquigarrow v$, meaning condition (2) fails.

### Identifying the Direct Child

Let $R(u)$ denote the number of vertices $v$ with $u \rightsquigarrow v$ (excluding $u$ itself). Among all vertices reachable from $u$, let

$$
v^* = \operatorname*{arg\,max}_{v:\, u \rightsquigarrow v} R(v).
$$

> [!claim]
> There is a direct edge $u \to v^*$.

**Proof.** If not, there exists $w$ such that $u \rightsquigarrow w \rightsquigarrow v^*$. Then $w \rightsquigarrow v^*$ and $w$ can reach everything reachable from $v^*$, giving $R(w) > R(v^*)$, which contradicts the definition of $v^*$.

### Reconstruction Algorithm

For each node $u$, repeat until no node is reachable from $u$:

1. Find $v^*$ of $u$.
2. Record a directed edge $u \to v^*$.
3. Mark every node reachable from $v^*$ as no longer reachable from $u$.
